# NetAtlas data model

Status: Phase 1. Migration `0001_discovery` is implemented and applied automatically.
Later DNS, route, and monitoring tables do not exist yet.

## 1. Modeling principles

1. **Facts, inferences, and measurements are different records.**
   - An observation is something directly received or read (ARP entry, ICMP reply,
     mDNS record, DNS response, RTT sample).
   - An inference is a candidate property derived from evidence (manufacturer, category,
     OS, model).
   - A measurement is a time-bounded result with method and parameters (DNS duration,
     route hop RTT).
2. **A device is a logical profile, not an address.** IP and MAC are identifiers with
   validity windows.
3. **History is append-oriented.** Current profiles are derived views; observations are
   not overwritten.
4. **Unknown and conflict are first-class states.** A missing value is stored as absent
   plus a reason, not as a fabricated value.
5. **Correlated evidence is not independent evidence.** Evidence carries a `source_unit`
   identifying the protocol exchange it came from.
6. **Timestamps are UTC milliseconds** in storage (`*_ms` integer columns). Display
   converts to local time.
7. **IDs are UUIDv7** (time-ordered) generated by NetAtlas, except natural keys used in
   lookup tables (e.g. OUI prefix).

## 3. Identity model

### 3.1 Identifiers and validity

Every identifier row has `first_seen_ms` and `last_seen_ms`, plus the source that
provided it. The same value may appear more than once over time (address reuse,
duplicate hostnames), so `(kind, normalized)` is not unique. Queries select by
`(kind, normalized, last_seen_ms)`.

### 3.2 Linking rules

When a new observation arrives, candidate devices are resolved in this order:

1. **Strong stable identifiers** — UPnP UDN, SSH host key fingerprint, TLS certificate
   fingerprint, mDNS instance name (full service instance), NetBIOS name combined with
   segment. Exact match within the freshness window links to that device.
2. **MAC address** — a globally administered MAC match within the MAC freshness window
   (default 24 h, configurable) links to the device that last held it. A logical device
   may legitimately have multiple active MACs (for example Ethernet and Wi-Fi), but
   multiple MACs are merged only when a strong identifier or stable co-observation
   corroborates the link; otherwise they remain separate devices with an `uncertain`
   link candidate.
3. **Hostname / DNS name** — a match is only a candidate. It may corroborate a link but
   never merges devices on its own.
4. **IP address** — never sufficient to merge. If an IP is seen with a different MAC,
   record `address_reuse_suspected` and keep separate devices.
5. **Ambiguity** — if a new observation matches two devices, do not merge. Create an
   `identity_links` row with status `uncertain` and explain the competing matches.

A device changing IP keeps its identity because the MAC (or stronger identifier) links
it. Two devices reusing an IP stay separate because IP alone never merges.

### 3.3 Locally administered MAC addresses

If the second-least-significant bit of the first octet is set, the address is locally
administered. NetAtlas records this and:

- does not present OUI output as the device manufacturer;
- labels the condition `locally_administered_mac` (not automatically "randomized",
  because hypervisors and manually assigned addresses also set this bit);
- requires corroborating identifiers for identity links when the MAC is the only
  candidate.

### 3.4 Uncertain links

```rust
pub struct IdentityLink {
    pub id: Uuid,
    pub from_device_id: DeviceId,
    pub to_device_id: DeviceId,
    pub basis: String,
    pub confidence: Confidence,
    pub status: LinkStatus,           // accepted / rejected / uncertain
    pub rationale: String,
    pub created_at_ms: i64,
}
```

Links are never destructive. Rejecting a link preserves both device histories.

## 4. Evidence and confidence

### 4.1 Evidence unit

An evidence row supports one candidate value for one property of one device. It always
references the observation that produced it and carries a `source_unit` such as:

```
ssdp:<udn>:description:<sha256-of-body>
mdns:<instance-fullname>:<record-type>
oui:<prefix>:<db-version>
icmp:<address>:<session-id>
```

Two fields extracted from the same SSDP description share one `source_unit` and count
as one source. A second, independent protocol observation gets a different unit.

### 4.2 Confidence levels

`high`, `medium`, `low`, `unknown`.

The rubric is qualitative and documented; NetAtlas does not present a numeric
probability. Aggregation:

1. Each evidence item has a base strength derived from the source class and property
   (see `docs/identification.md`).
2. The result starts at the strongest item's level.
3. If at least two **independent** items agree, raise one level, capped at `high`.
4. If independent items conflict, keep the conflicting values, set status `conflicted`,
   and lower the displayed confidence by one level (never below `unknown`).
5. Only weak evidence yields at most `low`.
6. Expired evidence does not support a current inference; the inference becomes
   `unknown` with reason `stale_evidence` unless fresh evidence exists.

### 4.3 Example records

Observation (fact):

```json
{
  "kind": "neighbor_entry",
  "subject": {"type": "segment", "id": "..."},
  "value": {"ip": "192.168.1.42", "mac": "3c:cd:5d:11:22:33", "state": "REACHABLE"},
  "source": "neighbor_table",
  "method": "netlink_rtm_getneigh",
  "observed_at_ms": 1790000000000
}
```

Evidence (supports a property):

```json
{
  "property": "manufacturer",
  "candidate": "Xiaomi Communications Co Ltd",
  "source": "oui_registry",
  "source_unit": "oui:3ccd5d:ieee-2026-11",
  "confidence": "medium",
  "rationale": "MAC prefix 3C:CD:5D is registered to Xiaomi; this is an address allocation, not proof of the device model."
}
```

Inference (conclusion):

```json
{
  "property": "manufacturer",
  "value": "Xiaomi Communications Co Ltd",
  "confidence": "medium",
  "status": "supported",
  "evidence_ids": ["..."],
  "rationale": "Single OUI association; no independent corroboration."
}
```

## 5. SQLite schema

Migration `0001_discovery.sql` (Phase 1). DNS, route, and monitoring tables are added
by later migrations.

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE schema_migrations (
    version     INTEGER PRIMARY KEY,
    name        TEXT NOT NULL,
    applied_at_ms INTEGER NOT NULL
);

CREATE TABLE app_meta (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);

CREATE TABLE interfaces (
    id            TEXT PRIMARY KEY,
    name          TEXT NOT NULL,
    index_no      INTEGER,
    mac           TEXT,
    mtu           INTEGER,
    is_up         INTEGER NOT NULL,
    is_loopback   INTEGER NOT NULL,
    first_seen_ms INTEGER NOT NULL,
    last_seen_ms  INTEGER NOT NULL
);

CREATE TABLE interface_addresses (
    id            TEXT PRIMARY KEY,
    interface_id  TEXT NOT NULL REFERENCES interfaces(id) ON DELETE CASCADE,
    address       TEXT NOT NULL,
    prefix_len    INTEGER NOT NULL,
    family        INTEGER NOT NULL,       -- 4 or 6
    scope         TEXT,
    first_seen_ms INTEGER NOT NULL,
    last_seen_ms  INTEGER NOT NULL
);
CREATE INDEX idx_ifaddr_interface ON interface_addresses(interface_id);

CREATE TABLE network_segments (
    id            TEXT PRIMARY KEY,
    interface_id  TEXT NOT NULL REFERENCES interfaces(id) ON DELETE CASCADE,
    prefix        TEXT NOT NULL,          -- CIDR, e.g. 192.168.1.0/24
    gateway       TEXT,
    first_seen_ms INTEGER NOT NULL,
    last_seen_ms  INTEGER NOT NULL,
    UNIQUE(interface_id, prefix)
);

CREATE TABLE scan_sessions (
    id            TEXT PRIMARY KEY,
    scope_json    TEXT NOT NULL,
    methods_json  TEXT NOT NULL,
    config_json   TEXT NOT NULL,
    started_at_ms INTEGER NOT NULL,
    finished_at_ms INTEGER,
    status        TEXT NOT NULL
                  CHECK (status IN ('running','completed','partial','cancelled','failed','interrupted')),
    errors_json   TEXT NOT NULL DEFAULT '[]'
);
CREATE INDEX idx_sessions_started ON scan_sessions(started_at_ms);

CREATE TABLE devices (
    id            TEXT PRIMARY KEY,
    label         TEXT,
    first_seen_ms INTEGER NOT NULL,
    last_seen_ms  INTEGER NOT NULL,
    merged_into   TEXT REFERENCES devices(id)
);

CREATE TABLE device_identifiers (
    id            TEXT PRIMARY KEY,
    device_id     TEXT NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    kind          TEXT NOT NULL,
    value         TEXT NOT NULL,
    normalized    TEXT NOT NULL,
    source        TEXT NOT NULL,
    first_seen_ms INTEGER NOT NULL,
    last_seen_ms  INTEGER NOT NULL,
    confidence    TEXT NOT NULL CHECK (confidence IN ('high','medium','low','unknown')),
    details_json  TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX idx_ident_lookup ON device_identifiers(kind, normalized, last_seen_ms);
CREATE INDEX idx_ident_device ON device_identifiers(device_id, last_seen_ms);

CREATE TABLE identity_links (
    id             TEXT PRIMARY KEY,
    from_device_id TEXT NOT NULL REFERENCES devices(id),
    to_device_id   TEXT NOT NULL REFERENCES devices(id),
    basis          TEXT NOT NULL,
    confidence     TEXT NOT NULL CHECK (confidence IN ('high','medium','low','unknown')),
    status         TEXT NOT NULL CHECK (status IN ('accepted','rejected','uncertain')),
    rationale      TEXT NOT NULL,
    created_at_ms  INTEGER NOT NULL,
    CHECK (from_device_id <> to_device_id)
);

CREATE TABLE observations (
    id             TEXT PRIMARY KEY,
    session_id     TEXT REFERENCES scan_sessions(id),
    subject_type   TEXT NOT NULL,         -- device, identifier, segment, interface, service
    subject_id     TEXT NOT NULL,
    kind           TEXT NOT NULL,
    property       TEXT,
    value_json     TEXT NOT NULL,
    source         TEXT NOT NULL,
    method         TEXT NOT NULL,
    observed_at_ms INTEGER NOT NULL,
    expires_at_ms  INTEGER,
    details_json   TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX idx_obs_subject ON observations(subject_type, subject_id, observed_at_ms);
CREATE INDEX idx_obs_session ON observations(session_id);

CREATE TABLE evidence (
    id             TEXT PRIMARY KEY,
    observation_id TEXT NOT NULL REFERENCES observations(id) ON DELETE CASCADE,
    device_id      TEXT REFERENCES devices(id) ON DELETE CASCADE,
    property       TEXT NOT NULL,
    candidate_json TEXT NOT NULL,
    source         TEXT NOT NULL,
    source_unit    TEXT NOT NULL,
    confidence     TEXT NOT NULL CHECK (confidence IN ('high','medium','low','unknown')),
    rationale      TEXT NOT NULL,
    observed_at_ms INTEGER NOT NULL,
    expires_at_ms  INTEGER
);
CREATE INDEX idx_evidence_device_prop ON evidence(device_id, property, observed_at_ms);
CREATE INDEX idx_evidence_unit ON evidence(source_unit);

CREATE TABLE inferences (
    id               TEXT PRIMARY KEY,
    device_id        TEXT NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    property         TEXT NOT NULL,
    value_json       TEXT,
    confidence       TEXT NOT NULL CHECK (confidence IN ('high','medium','low','unknown')),
    status           TEXT NOT NULL CHECK (status IN ('supported','conflicted','unknown')),
    rationale        TEXT NOT NULL,
    evidence_ids_json TEXT NOT NULL,
    computed_at_ms   INTEGER NOT NULL
);
CREATE INDEX idx_inference_device ON inferences(device_id, property, computed_at_ms);

CREATE TABLE services (
    id             TEXT PRIMARY KEY,
    device_id      TEXT NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    ip             TEXT NOT NULL,
    port           INTEGER NOT NULL,
    transport      TEXT NOT NULL CHECK (transport IN ('tcp','udp')),
    protocol       TEXT,
    product        TEXT,
    version        TEXT,
    banner         TEXT,
    tls_json       TEXT,
    source         TEXT NOT NULL,
    observed_at_ms INTEGER NOT NULL,
    details_json   TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX idx_services_device ON services(device_id, observed_at_ms);

CREATE TABLE oui_sources (
    id             TEXT PRIMARY KEY,
    name           TEXT NOT NULL,
    version        TEXT,
    source_url     TEXT,
    content_sha256 TEXT NOT NULL,
    imported_at_ms INTEGER NOT NULL,
    record_count   INTEGER NOT NULL
);

CREATE TABLE oui_prefixes (
    prefix_hex   TEXT NOT NULL,
    prefix_bits  INTEGER NOT NULL,
    organization TEXT NOT NULL,
    address      TEXT,
    country      TEXT,
    source_id    TEXT NOT NULL REFERENCES oui_sources(id) ON DELETE CASCADE,
    PRIMARY KEY (prefix_hex, prefix_bits, source_id)
);
CREATE INDEX idx_oui_lookup ON oui_prefixes(prefix_bits, prefix_hex);
```

## 6. Migrations and integrity

- Migrations are numbered SQL files embedded in the binary, applied inside a
  transaction, in order. `PRAGMA user_version` and `schema_migrations` must agree.
- A migration failure rolls back and leaves the previous version intact.
- Foreign keys are enabled on every connection.
- WAL mode is enabled for concurrent reads while a scan writes.
- The writer serializes writes; readers use separate connections.
- On startup, a session left in `running` from a previous process is marked
  `interrupted`; its observations remain valid.
- Destructive migrations require an explicit backup step and are avoided otherwise.

## 7. Retention and freshness

Default retention (configurable, not yet implemented):

| Data | Default |
| --- | --- |
| Raw observations | 180 days |
| Evidence | 180 days |
| Inferences | latest per device/property plus 90 days of history |
| Scan sessions | 365 days |
| DNS/route measurements | 365 days |
| Device rows | kept while referenced by any observation |

Freshness windows used by identification:

| Identifier | Default validity |
| --- | --- |
| Neighbour/ICMP presence | 10 minutes |
| IP identifier | 24 hours |
| MAC identifier (global) | 24 hours |
| Hostname | 7 days (marked stale sooner if contradicted) |
| UPnP UDN / mDNS instance / host key | 30 days |

These are defaults, not hard-coded truth; they are recorded in session config so a
historical inference can be explained.

## 8. Import/export mapping (later phases)

- JSON export preserves full records including evidence, inference rationale, and
  timestamps.
- CSV is lossy: it can carry device rows, identifiers, and current inferences, but not
  the full evidence graph. The CSV header/docs will state which fields are omitted.
- Import is versioned, validated, dry-runnable, and transactional. Duplicate detection
  is by stable IDs plus natural keys; conflicts are reported, never silently merged.
- SQLite backup/restore uses the SQLite backup API or a consistent file copy while the
  database is quiescent, followed by integrity checks.
